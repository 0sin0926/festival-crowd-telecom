# 모델과 데이터 정리

> 인구 시계열 예측 파트에서 **어떤 데이터를 썼고, 회귀 분석에 어떤 모델을 비교해 무엇을 골랐는지**를 한 문서로 정리한 것.
> 작업 과정과 논의 경위는 `docs/작업기록.md`에 있다. 이 문서는 결과만 담는다.

작성: 2026-10-13

---

## 1. 한눈에

- **예측하는 것**: 불꽃축제 날 여의도의 구역별 × 1시간 단위 인원
- **계산식**: 예측 인원 = 평소 인원 + 축제 증가분 × 보정 계수
- **회귀 모델이 맡는 부분**: 평소 인원 (축제가 없었다면 그 시각 그 구역에 있었을 사람 수)
- **고른 모델**: 그래디언트 부스팅 회귀 (scikit-learn `HistGradientBoostingRegressor`, 기본 설정)
- **고른 이유**: 6가지 방법을 4구간 시계열 교차검증으로 비교했을 때 오차가 가장 작았음 (6구역 평균 오차율 14.2%. 단순 평균 22~23%, 선형회귀 21.4%, 랜덤포레스트 15.0%)
- **쓴 데이터**: 서울 생활인구(통신 데이터 기반 추계 인구), 시간별 날씨, 서울시 문화행사 정보, 공휴일

**받은 범위**

| 용도 | 기간 | 양 |
|---|---|---|
| 평소 모델 학습·검증 | 2023.01~2026.07 (43개월, 1,301일) | 원본 약 52GB |
| 과거 불꽃축제 | 2017.09, 2018.10, 2019.10, 2022.10 (4개월) | 원본 약 2.6GB |

- 원본은 서울 전체가 월별 ZIP 한 파일(약 1.2GB)로만 제공됨. 받는 즉시 **여의동(행정동코드 11560540)의 68개 집계구만** 추출하고 원본은 삭제. 남긴 양은 약 180MB
- 2023년 이전의 평소 데이터를 받지 않은 이유는 `docs/작업기록.md` 6-4 참고 (2017~2019년은 평소 수준이 지금과 달랐음을 확인)

**알아야 할 특성과 한계**
- 통신 "사용량"이 아니라 "그 자리에 있는 사람 수"다. 데이터 트래픽이나 통화량 정보는 없다
- 개인정보 보호를 위해 3명 이하는 `*`로 가려져 있음 → 0으로 처리 (총인구에는 거의 해당 없음)
- 초대형 인파에서 추정이 얼마나 정확한지는 확인된 바 없음. 언론이 보도하는 "100만 명" 같은 수치와 직접 비교할 수 없음
- 원본 누락: 2019-10-15~27 (통신수집기 장비 고장, 공식 안내), 2026-05-02와 05-04~09 (파일이 비어 있음, 직접 확인)
- 형식 불일치: 2019년 이전 파일은 UTF-8, 이후는 CP949. 2024-06-20 하루는 코드 뒤 공백과 시각 한 자리 표기 → 읽을 때 맞춰 줌
- 2017~2019년과 2022년 이후 사이에 추정 방식이 바뀌었는지는 확인하지 못함

## 3. 전처리 흐름

| 단계 | 하는 일 | 남는 양 |
|---|---|---|
| 1 | 서울 전체 생활인구 원본 (47개월) | 약 55GB, 하루 약 46만 행 |
| 2 | 여의동 68개 집계구만 추출 | 약 180MB (전체의 0.4%) |
| 3 | 5개 구역 + 그 외 + 여의동 전체로 묶어 시간별 표로 | 33,864시간 (1,411일) |
| 4 | 시간별 날씨와 달력 정보(요일, 공휴일, 계절)를 시각 기준으로 결합 | 같음 |
| 5 | 학습 기간(2023.01~2026.07)만 | 1,301일 |
| 6 | 평일 제외 (토·일·공휴일만) | 429일 |
| 7 | 행사일 제외 | **367일, 약 8,800시간** ← 평소 모델의 학습·검증 표본 |

- 평일을 뺀 이유: 여의도는 업무지구라 평일 낮 인원이 주말의 약 2배. 축제는 주말에 열리므로 비교 기준도 주말이어야 함
- 행사일을 뺀 이유: "축제가 없는 날"의 인원을 배워야 하므로

## 4. 회귀 분석 — 평소 인원 모델

### 4-1. 문제 정의

| 항목 | 내용 |
|---|---|
| 예측 대상 | 한 구역의 한 시간 인원 (명) |
| 모델 수 | 구역마다 하나씩, 6개 |
| 변환 | 인원에 로그를 씌워 학습하고(`log(1+인원)`), 예측 뒤에 되돌림. 인원이 수백 명에서 수십만 명까지 퍼져 있어서 |
| 표본 | 2023.01~2026.07의 행사 없는 토·일·공휴일 367일 × 24시간 |

### 4-2. 입력 변수 (18개)

| 묶음 | 변수 |
|---|---|
| 시각 | 시각(0~23) |
| 요일·공휴일 | 요일, 공휴일 여부, 요일 유형(토 / 일·공휴일), 다음 날이 쉬는 날인지 |
| 계절 | 월, 1년 주기를 나타내는 값 2개(sin, cos) |
| 추세 | 2023-01-01부터 지난 날 수 |
| 기온 | 기온, 체감온도 |
| 비·눈 | 그 시간 강수량, 최근 3시간 강수량, 그날 하루 강수량, 적설 |
| 그 밖의 날씨 | 상대습도, 풍속, 구름량 |

### 4-3. 비교한 방법

| # | 방법 | 설명 |
|---|---|---|
| 1 | 요일유형×시간 평균 | 모델 없이, 학습 기간의 같은 요일 유형·같은 시각 평균을 그대로 씀. 가장 단순한 기준 |
| 2 | 월×요일유형×시간 평균 | 1번에 월을 더해 계절을 반영 |
| 3 | 선형회귀 (Ridge) | 요일유형×시각 조합, 월을 범주로 넣고 날씨·추세를 더한 선형 모델. 규제 강도 1.0 |
| 4 | 랜덤포레스트 | 나무 300그루, 잎 최소 3개 |
| 5 | 그래디언트 부스팅 (기본 설정) | `HistGradientBoostingRegressor`. 반복 400회, 학습률 0.05, 잎 최대 31개, L2 규제 1.0 |
| 6 | 그래디언트 부스팅 (튜닝) | 설정 후보 8개 중 구간·구역마다 가장 좋은 것을 골라 씀 |

변수 제거 실험 (5번에서 변수를 빼 보고 오차가 얼마나 느는지)

| # | 실험 |
|---|---|
| 7 | 날씨 변수 9개 제거 |
| 8 | 추세 변수 제거 |
| 9 | 날씨·추세 모두 제거 (달력만) |

### 4-4. 검증 방법

- **시계열 교차검증**: 뒤쪽 6개월씩 4구간을 차례로 검증 구간으로 두고, 그 앞의 전체 기간으로 학습. 미래 데이터로 과거를 맞히는 일이 없도록 시간 순서를 지킴

| 구간 | 학습 | 검증 |
|---|---|---|
| 1 | ~2024.06 | 2024.07~12 |
| 2 | ~2024.12 | 2025.01~06 |
| 3 | ~2025.06 | 2025.07~12 |
| 4 | ~2025.12 | 2026.01~07 |

**학습(train) / 시험(test) 나누기 요약**
- 나눠서 했다. 문서의 오차율은 모두 모델이 학습 때 보지 못한 시험 기간에서 잰 값
- 무작위로 섞지 않고 **시간 순서로** 나눔 (앞 기간으로 학습, 뒤 기간으로 시험). 섞으면 같은 날의 14시는 학습에, 15시는 시험에 들어가 점수가 실제보다 좋게 나오기 때문
- 한 번이 아니라 위 표처럼 네 번 나눠 평균을 냄
- 튜닝 때는 학습 기간 안에서 마지막 20%를 따로 떼어 설정을 고름 (학습 / 설정 고르기용 / 시험의 세 덩어리)
- 불꽃축제 예측은 4회뿐이라 기간으로 나누지 않고, 한 회를 빼고 나머지 3회로 맞혀 보기를 네 번 반복 (5장)
- 검증으로 방법을 고른 뒤 실제 예측에 쓰는 모델은 나누지 않고 전체 367일로 학습

- **평가 지표**: 오차율 MAPE(%)와 평균 오차 MAE(명). 4구간 평균으로 비교
- **튜닝**: 후보마다 학습 구간의 마지막 20% 날짜로 평가해 고름. 검증 구간은 튜닝에 쓰지 않음
  - 후보 8개: 학습률 {0.05, 0.1} × 잎 최대 {7, 15, 31} 6가지 + 잎 최소 표본 50으로 늘린 것 + L2 규제를 0으로 둔 것

### 4-6. 선택과 이유

**그래디언트 부스팅 (기본 설정)을 채택**

- 6구역 평균 오차율이 가장 낮음 (14.2%). 방법 1~5 가운데 4개 구역(공원 동쪽, 진입부, 서여의도, 동남쪽 끝)에서 가장 좋고, 나머지 2개(업무지구, 여의동 전체)는 랜덤포레스트가 0.1~0.3%p 앞섬
- 랜덤포레스트(15.0%)와 차이는 크지 않음. 강변 구역(공원 동쪽, 진입부)에서 그래디언트 부스팅이 더 나음
- 선형회귀(21.4%)는 단순 평균(22~23%)과 별 차이가 없음. 요일·시각·날씨의 효과가 서로 얽혀 있어서(예: 기온의 효과가 시각마다 다름) 선형 모델로는 잘 잡히지 않음
- **튜닝은 효과가 없었음** (14.2% → 14.2%). 후보 8개의 점수가 13.1~13.3%로 거의 같았음. 그래서 설정을 바꾸지 않고 기본값을 씀

**최종 설정** (`scripts/baseline_model.py`의 `MODEL_PARAMS`)

| 설정 | 값 |

| 모델 | scikit-learn `HistGradientBoostingRegressor` |
| 반복 횟수 | 400 |
| 학습률 | 0.05 |
| 잎 최대 수 | 31 |

### 4-7. 변수가 얼마나 기여하는가

**변수 제거 실험에서**
- 날씨를 빼면 강변 구역만 나빠짐: 공원 동쪽 24.9 → 29.7%, 진입부 18.8 → 23.7%. 업무지구(8.4 → 8.4%)와 동남쪽 끝은 변화 없음 → 날씨는 야외 구역에서만 의미가 있음
- 추세를 빼면 더 크게 나빠짐: 공원 동쪽 24.9 → 37.0%, 동남쪽 끝 14.8 → 22.7% → 평소 수준이 3년 사이에 조금씩 변하고 있음
- 달력만 쓰면 단순 평균 수준(21.3%)으로 돌아감

**변수 묶음별 중요도** (마지막 구간에서 그 묶음의 값을 뒤섞었을 때 오차율이 느는 정도, %p)

| 변수 묶음 | 공원 동쪽 | 진입부 | 서여의도 | 동남쪽 끝 | 업무지구 | 여의동 전체 |
|---|---|---|---|---|---|---|
| 시각 | 82.3 | 63.5 | 51.8 | 78.6 | 62.7 | 23.1 |
| 요일·공휴일 | 1.4 | 0.7 | 14.5 | 4.3 | 5.6 | 3.1 |
| 계절 | 3.0 | 3.4 | 3.1 | 0.2 | 1.8 | 1.9 |
| 기온 | 8.7 | 8.2 | 0.5 | 0.0 | 0.1 | 0.0 |
| 비·눈 | 0.3 | 1.2 | 0.1 | −0.1 | 0.0 | 0.0 |

- 시각이 압도적으로 중요
- 그다음은 구역마다 다름: 강변(공원 동쪽·진입부)은 기온, 서여의도는 요일(일요일 오전 교회)
- 비·눈이 낮게 나오는 것은 비 오는 시간이 전체의 일부라서. 비 온 날만 놓고 보면 효과가 큼: 주말 낮 15~25도일 때 비가 오면 공원 동쪽 인원이 44% 적음 (4,243명 → 2,359명)
- 추세는 이 방법으로는 측정되지 않음 (검증 구간의 날짜가 모두 학습 기간 뒤라 모델 안에서 같은 값으로 취급됨). 추세의 효과는 위의 제거 실험으로 봄

### 4-8. 검증 과정에서 발견해 고친 것

- 처음 비교했을 때 서여의도의 한 구간 오차가 56%로 튐. 원인은 **2024-12-07, 12-14 국회 앞 집회**(여의동 전체 하루 최대 37만, 52만 명)가 문화행사 목록에 없어 "평소"로 학습된 것
- 뉴스로 확인한 집회 4일을 행사일로 추가한 뒤 다시 비교. 위 표는 모두 고친 뒤의 결과

## 5. 회귀가 아닌 부분 — 축제 증가분과 보정 계수

평소 모델 위에 얹는 두 값은 학습으로 구한 것이 아니라 **과거 실제 값에서 직접 계산**한 것이다.

| 값 | 구하는 법 | 쓴 회차 |
|---|---|---|
| 축제 증가분 | 불꽃축제일의 실제 인원 − 평소 모델의 예측. 시간대별·구역별 평균 | 2022, 2023, 2024, 2025년 (4회) |
| 보정 계수 (오전 비 후 갬) | 비 온 해의 증가분 ÷ 같은 시기 맑은 해의 평균 증가분. 시간대별·구역별 | 2018년 ÷ (2017, 2019년 평균) |

- 2017~2019년 회차의 평소는 최근 모델이 아니라 그 해 같은 달의 다른 토요일 값으로 잡음. 최근 모델을 과거에 적용하면 오차가 최근의 1.5~2배였기 때문 (업무지구는 8~13% 높게 예측. 2022년에는 최근과 같은 수준)
- 여의동 전체 피크 증가분: 2022~2025년 25.7만~30.3만 명 (평균 27.7만), 2017~2019년 18.9만~22.5만 명
- 보정 계수 예 (여의동 전체): 15시 0.45, 17시 0.72, 19시 0.92

**전체 예측의 검증** — 최근 4회를 하나씩 빼고 나머지 3회로 맞혀 보기

|---|---|---|

## 6. 한계

**데이터**
- 생활인구는 통신 신호로 추정한 값이고 내국인만 포함한다
- 날씨는 관측값이 아니라 재분석값이다
- 행사 달력에 빠진 행사(특히 집회)가 평소 표본에 남아 있을 수 있다
- 공휴일 일부는 기억 기준으로 넣었다

**모델**
- 평소 모델의 오차율은 구역에 따라 6~25%. 인원이 적은 강변 구역일수록 오차율이 높다 (명 수로는 300~400명)
- 학습 기간이 3년 7개월이라 장기 추세를 안정적으로 배웠다고 하기 어렵다. 2026년 8월 이후는 추세 변수가 마지막 수준에 고정된다
- 튜닝 후보는 8개로 좁게 잡았다

**예측**
- 불꽃축제만 예측한다
- 축제 증가분은 4회, 비 온 날 보정 계수는 1회로 만든 것이라 표본이 매우 작다
- 2026년 8월 이후는 같은 기준의 실제 값이 없어 예측이 맞았는지 확인할 수 없다
